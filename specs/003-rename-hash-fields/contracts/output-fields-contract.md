# Contract: Output Field Names

**Feature**: `specs/003-rename-hash-fields/spec.md` | **Date**: 2026-10-18

The CLI's externally observable interfaces for this feature are the on-disk
output files (CSV/JSON) plus README documentation of them. Internal model field
names are explicitly **not** part of this contract. See `../data-model.md` for
entity internals and `../research.md` for rationale.

## 1. CSV contract

Header row, in order (differences from pre-change marked):

```text
name, folderName, typeLabel, type, login_uris, login_username, login_password,
login_password_<alg>,                  ← was login_password_hash
login_password_leaks,                  ← login_password_hash_type column REMOVED
login_password_readable_leaks, login_password_compact_leaks, login_totp, hasTotp,
uriCount, passwordAgeDays, reprompt, repromptLabel, notes, organizationId, deletedDate
```

- `<alg>` ∈ {`sha1`, `ntlm`} — lowercase, one value per file (FR-004).
- Hash values: uppercase hex, unchanged (FR-005).
- Row values, ordering, and formatting outside the renamed/removed columns are
  byte-identical to pre-change output for identical input (SC-004).

## 2. JSON contract

Top-level: array of groups. Group object keys, in order:

```text
hash_<alg>, leaks, passwordObjects      ← was hash, leaks, passwordObjects
```

Each element of `passwordObjects` (nested variant), hash-relevant keys in order:

```text
... login, login_password_<alg>, login_password_leaks,
    login_password_readable_leaks, login_password_compact_leaks ...
```

(flat variant analogously; key order otherwise per existing
`JSON_KEY_ORDER_NESTED`/`JSON_KEY_ORDER_FLAT`.)

- Exactly one of `login_password_sha1` / `login_password_ntlm` per record;
  exactly one of `hash_sha1` / `hash_ntlm` per group; tokens identical
  throughout the file (FR-004).
- `login_password_hash`, `login_password_hash_type`, and group-level `hash`
  MUST NOT appear (SC-003).

## 3. Naming inputs

| Run mode | Effective type → token | Example record field |
|---|---|---|
| explicit `HASH_TYPE=sha1` / `ntlm` | as requested | `login_password_ntlm` |
| `auto` + local corpus detected | detected type | per detection |
| `auto` + mismatch + `HASH_TYPE_MISMATCH=warn` | **corrected** type, never requested | requested sha1 + ntlm corpus → `login_password_ntlm` |
| `auto` in API mode | `sha1` (api-default) | `login_password_sha1` |
| no selection (writer default) | `sha1` | `login_password_sha1` |

## 4. Documentation & tooling surface (FR-007/FR-008)

- **README.md**: zero remaining references to `login_password_hash`,
  `login_password_hash_type`, or group-level `hash` (currently L77, L244).
- **Shipped scripts**: `manual-testing-sha1/scripts/compare-outputs.mjs`,
  `manual-testing-ntlm/scripts/compare-outputs.mjs`,
  `manual-testing-ntlm/scripts/compare-cross-plan.mjs` parse the new field
  names; no legacy fallbacks.
- **Exempt**: `manual-testing-*/reports/*.md` (historical, per clarification);
  generated `manual-testing-*/output/*` (untracked, regenerated by the manual
  suites); internal types (`HashWithLeaksAndPasswordObjects.hash`);
  console/dry-run output.

## 5. Breaking-change statement

Clean break, no aliases/dual emission (spec Assumptions): external consumers
reading legacy names will find nothing. Accepted.
